# 設計

## 技術構成

- バックエンド: Python + FastAPI + Uvicorn（個人向けローカルサーバ）。
- 画面骨格: Jinja2。ビューアの挙動は素の JS（重いフレームワークは使わない）。
- 保存: SQLite 1ファイル（`data/app.db`）に文書レジストリ（documents）・PDF/HTML の穴（blanks）・
  穴ごとの正誤履歴（attempts）。
  - Markdown の穴は**元ファイル内の記法が正本**で DB には持たない（二重管理の回避）。
  - PDF の穴は DB（blanks）で管理する。元 PDF は変更しない。
- パス登録: フォームのパスは引用符・`file://` URL・`~`/環境変数・Unicode 正規化（NFC/NFD）ゆらぎを
  吸収して解決する。見つからない場合は「試したパス」を添えて表示し、自己診断できるようにする。
- Markdown 描画: markdown-it-py。ブロックトークンの `map`（元ソース行）を各ブロック要素へ
  `data-ls`/`data-le` として付与し、アプリ上の選択→元ソース位置特定に使う。
- PDF 描画: PDF.js 3.11.174（`static/vendor/pdfjs/` に同梱＝オフライン動作）。元 PDF は `raw` で配信し
  クライアントで canvas 描画＋テキストレイヤ生成。
- HTML 表示: 元 HTML と同階層の資材を `asset` で**同一オリジン配信**し、`iframe`
  （`sandbox="allow-same-origin allow-scripts"`）に表示。親ページの JS が同一オリジンの iframe DOM を
  直接操作してマスクを重ねる（元ファイルは無改変）。
  - `allow-scripts` は必須: これが無い sandbox フレームは、親が iframe DOM を変更すると Chrome が描画を
    破棄して**空白化**する。`allow-same-origin` は親が DOM を操作するために必須。両者併用でも上部
    ナビゲーション/ポップアップ/フォーム等は sandbox が引き続き抑止する。
  - iframe の `src` は**テンプレートのマークアップで出力**する（JS で `.src` 代入すると sandbox フレームで
    描画されない個体があるため）。
  - iframe は実ビューポート高（`height: calc(100vh - …)`）を持ち**内部スクロール**で閲覧する。元ページが
    高さをビューポート基準（`height:100%`/`100vh`）で組むことがあり、`scrollHeight` 追従だと高さが伸びず
    空白化するため。矩形マスクは `position:fixed` のオーバーレイに載せ、scroll/resize で再配置する。
  - **表示を登録ページに固定（別 URL へ遷移させない）**: 外部資材（フォント・画像等）の読み込みは許容し、
    見た目は元のまま。狙いは「登録した HTML 以外のページに飛ばない」こと（別ページに隠しがあるかも、という
    混乱を避ける）。多層で固定する:
    - リンク遷移の無効化: `htmlviewer.js` が iframe 内のリンククリック（`a[href]`）とフォーム送信を
      `preventDefault` で止める。ただし同一ページ内アンカー（`#...`）と `javascript:` はスクロール/操作のため許可。
    - 引き戻し（安全網）: 最初に読めた URL を基準に保持し、iframe が別 URL へ遷移したら（リンクをすり抜けた・
      ページ自身のスクリプトが遷移した等）`location.replace` で元ページへ戻す。連続自動遷移の暴走対策に回数制限。
    - 初期化ガードは真偽値でなく「その文書に overlay が注入済みか」で判定し、引き戻し後の再読込でもマスクを
      貼り直せるようにする。

## 穴（クローズ）の方式

- 記法: `{{cN::answer}}`（N は識別用の番号。初期は各穴独立で、グループ表示の意味は持たせない）。
- 描画: Markdown→HTML 変換後に記法を `<span class="cloze" data-cloze="N">answer</span>` へ置換。
- マスク: 実践モードで文字色を透明＋背景ブロックにし、**元の文字幅を保ったまま**隠す（レイアウト不変）。
  クリックで `.revealed` をトグル。表示状態は永続化しない（次回は全隠しで開始）。
- 作成（アプリ上選択）: 「ブロックの元ソース行範囲＋選択文字列＋ブロック内の出現番目」で元ソースの位置を
  特定し、記法を挿入。既存の穴と重なる範囲は拒否（初期仕様）。
- 削除: 指定番号の記法を外し、中身の文字列だけ残す。

### PDF（Blank・DB 管理）

- 穴 = ページ内の**正規化矩形(0〜1)のリスト**（拡大率・ウィンドウ幅に依存しない）。種別は text / rect。
- テキスト選択: 選択範囲のクライアント矩形を行ごとにまとめて正規化し、1つの穴（複数矩形）として保存。
- 矩形選択: 作成モードの「矩形」ツールでドラッグした1矩形を保存（図・画像向け。文字認識は不要）。
- マスク: 元位置に重ねた div。実践はクリックで同一穴の全矩形を一括で表示/非表示。答え文字列は保存しない
  （マスクを外すと元の内容が見える）。
- 重なり: 同一ページで既存の穴と矩形が重なる登録は拒否（初期仕様）。

### HTML（Blank・DB 管理・リフロー耐性）

HTML はウィンドウ幅・フォントでリフローするため、PDF のようなページ内絶対座標では穴を保持できない。
座標でなく**アンカー**で持ち、`blanks.payload`(JSON) に保存する（PDF の `rects` とは別列）。

- text: `{exact, prefix, suffix}`（テキストアンカー）。描画時に本文の連結文字列から前後文脈を優先して
  一致箇所を再探索し、該当範囲を `<span class="cc-text">` で包む（複数ノードに跨り得る）。リフロー追従。
- rect: `{selector, x, y, w, h}`（対象要素の CSS セレクタ＋要素内の正規化サブ矩形）。描画時に要素を
  見つけ、その矩形上に絶対配置のマスクを重ねる。要素基準なのでリフロー時も再計算で追従する。
- マスク: 実践はクリックで表示/非表示。答え文字列は保存しない（外すと元内容が見える）。
- 重なり: 同一アンカーの重複登録はサーバで拒否。範囲の重なりはクライアントが選択範囲の DOM を見て拒否
  （サーバは DOM を持たないため。初期仕様）。

### 穴の作成（2段階・PDF/HTML 共通）

- 作成モードでテキストをドラッグ、または矩形をドラッグすると、その場では作らず**「作成待ち」**にする
  （テキストは選択を、矩形はプレビュー枠を残す）。ツールバーの**「穴を作成」**を押して確定する。
  モード/ツール切替や新しいドラッグで作成待ちは破棄する。即時作成だと誤操作で穴が増えるのを避けるため。
- 実践モードでは作成ツール（テキスト選択/矩形の切替・「穴を作成」）は出さない。CSS は `.create-tools` に
  `display` を与えるので、`[hidden]` 属性の UA 規定を上書きしないよう `.create-tools[hidden]{display:none}` を明示する。

### マスクの枠線（PDF/HTML 共通）

- テキスト穴・矩形穴とも、隠蔽時は塗り＋枠線、**表示（revealed）時も枠線を残す**（塗りは消える）。
  これにより「元々どこが穴だったか」を表示後も位置として確認できる。
- HTML の作成モードで穴（マスク）を再クリックすると削除する。確認ダイアログは**親ウィンドウの `confirm`**
  を使う（sandbox の iframe は `allow-modals` が無く `iframe.confirm` が常に false を返し削除できないため）。

### 正誤記録（attempts・PDF/HTML 共通）

- 穴ごとに「正解/不正解」ボタンを持ち、押すと `attempts`（doc_id, blank_id, result, created_at）へ
  **いつ正解/不正解したかを1件ずつ記録**する（履歴として残す）。記録は実践モードのみ。
- 画面には穴の右上に、これまでの**正解数・不正解数**を表示する（実践・作成の双方）。穴を表示
  （revealed）すると、この回数表示もマスクと同様に隠れる。
- PDF は blank-layer 内の絶対配置、HTML は固定オーバーレイ内に置き各穴の矩形右上へ配置（内部スクロールに
  追従）。穴を削除すると、その正誤履歴も併せて削除する。

### メモ（note・PDF/HTML 共通）

- 穴ごとに自由記述の**メモ**を持つ（`blanks.note`・既存 DB は migration で追加）。正誤ボタンの隣に「✎」を置く。
- 作成モード: 「✎」でプロンプト編集して保存（登録済みなら「✎」を強調表示）。
- 実践モード: 「✎」クリックでメモ本文の表示/非表示を切り替える。穴を表示（revealed）すると回数と同様に隠れる。

### HTML 図の表示（`<picture>` の壊れた source 対処）

- 「完全」保存は `<img src>` をローカル化しても `<source srcset>` を root 絶対パス（ローカル未保存）のまま
  残すことがあり、デスクトップ幅で図が出ない（PC版画像が保存されない）。描画前に各 `<picture>` を補正する:
  - 保存元サイトの origin を Chrome の「保存元 URL」コメント→`og:url`→`canonical` から求める。
  - origin が分かれば、ローカル未保存の root 絶対 `<source>` を**元サイトの絶対URLへ書き換えて外部から読む**
    （外部資材の読み込みは許容）。読めない場合（オフライン・404）は `<img>` の `error` でローカル保存版
    （多くはSP版）へ退避する。origin 不明なら `<source>` を外してローカルの `<img>` に委ねる。

## 既知の制約

### Markdown
- アプリ上の選択は**同一ブロック内のテキスト**を対象とする（ブロックをまたぐ選択は不可）。
- 選択語がブロック内で、装飾記法（`**`等）や既存の穴の中身と重複する場合、出現番目の対応が
  ずれて意図と違う箇所に入ることがある。元ソースの該当記法を直接直せば確実。
- 行をまたぐ（ソフト改行を含む）選択は、描画テキストと元ソースの空白差で見つからないことがある。
- コードブロック内の `{{cN::...}}` も穴として扱われる。

### PDF
- テキスト選択はページ内に文字情報がある PDF が対象（スキャン画像のみの PDF は矩形選択で対応）。
- 選択は同一ページ内のみ（ページをまたぐ選択は不可）。
- 表示は横幅フィット固定（拡大縮小 UI は未実装。座標は正規化保存なので後から追加しても穴はずれない）。

### HTML
- テキスト穴は `{exact, prefix, suffix}` による再探索のため、元 HTML の該当文言が編集・変化すると
  穴が外れることがある（その場合は作り直し）。同じ文言が前後文脈も含め完全一致で複数ある場合は先頭を採用。
- 矩形穴は対象要素の CSS セレクタ（`nth-of-type` ベース）に依存するため、元 HTML の構造が変わると
  外れることがある。マスクはビューポート基準（`position:fixed` オーバーレイ内）で対象要素の矩形に重ね、
  scroll/resize で再配置する。
- `sandbox="allow-same-origin allow-scripts"` のため**文書自身のスクリプトが動く**。ほとんどの保存ページは
  これで元サイトどおり描画できるが、スクリプトが iframe 自身を別 URL へ遷移させる保存ページでは表示が
  変わり得る。外部 http(s) 資材はネット接続時のみ読み込まれる（オフラインでは失敗しても致命的でない）。
- 同一オリジン配信＋スクリプト許可のため、**信頼できる自分の文書のみ**を登録する前提。
- 枠線: 矩形の穴は位置が分かりにくいので、隠蔽時は太枠、表示（revealed）時も破線枠を残して位置を示す。
